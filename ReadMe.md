# 2048-RL

A reinforcement learning project built from scratch to explore how different agents make decisions in the game of 2048 — from random action selection to reward-driven behavior, and eventually more advanced planning and learning algorithms.

The goal is to understand the underlying concepts by implementing agents incrementally, evaluating them under consistent conditions, and comparing their performance.

## Environment

The game environment wraps the 2048 game logic and exposes a simple interface for agents.

### Actions

The agent selects one of four actions:

| Action | Direction |
|---|---|
| `w` | Up |
| `a` | Left |
| `s` | Down |
| `d` | Right |

### Environment API

- `reset()` initializes a new game and returns the initial observation.
- `step(action)` executes an action and returns the next observation, reward, and termination status.
- `actions` exposes the available actions.

The underlying game logic handles tile movement, merging, tile spawning, scoring, and game-over detection.

### State Representation

The environment maintains the actual board as a 4 × 4 NumPy array.

The observation returned by the environment is flattened into a one-dimensional array. Non-zero tile values are transformed using base-2 logarithms, while empty cells remain zero.

This representation is intended to provide a compact input for future learning-based agents.

### Reward

The immediate reward is the score generated by merging tiles during a move. The current reward-driven agent uses this immediate reward to select actions.

## Implemented Agents

### 1. Random Agent

The Random Agent selects an action randomly from the available actions.

It does not evaluate the board, predict future outcomes, or learn from previous episodes.

**Purpose:** Establish a baseline against which more structured decision-making strategies can be evaluated.

### 2. Greedy Reward Agent

The Greedy Reward Agent evaluates all four possible actions and selects the action that produces the highest immediate merge reward.

Each hypothetical action is evaluated on a copy of the original board, ensuring that evaluating one action does not affect the others.

When multiple actions have the same reward, the agent prefers a move that changes the board over one that leaves it unchanged.

**Purpose:** Demonstrate greedy decision-making and the limitations of optimizing immediate reward without explicitly considering long-term consequences.

**Limitation:** The agent does not plan several moves ahead or evaluate the strategic quality of the resulting board. Consequently, it can make locally beneficial decisions that do not lead to strong long-term performance.

## Evaluation

The evaluation script runs an agent across multiple episodes and records per-episode results in CSV format.

### Metrics

| Metric | Description |
|---|---|
| Average Total Reward | Average accumulated merge reward per episode |
| Average Maximum Tile | Average value of the largest tile reached in each episode |
| Tile Reach Rates | Percentage of episodes reaching specified tile milestones |
| Average Moves to Tile | Average number of moves needed to reach a milestone, among successful episodes |
| Average Episode Length | Average number of moves per episode |
| Ineffective Move Rate | Percentage of actions that leave the board unchanged |

The current evaluation tracks tile milestones of 64, 128, 256, 512, and 2048.

### Evaluation Results

Both agents were evaluated over 1,000 episodes with seed 42.

| Metric | Random Agent | Greedy Reward Agent |
|---|---:|---:|
| Average Total Reward | 1,094.25 | 3,181.10 |
| Average Maximum Tile | 107.34 | 242.24 |
| Reached 64 | 93.30% | 99.80% |
| Reached 128 | 55.80% | 95.00% |
| Reached 256 | 7.70% | 63.60% |
| Reached 512 | 0.00% | 13.90% |
| Average Moves to 256 | 183.16 | 163.63 |
| Average Episode Length | 140.62 | 265.84 |
| Ineffective Move Rate | 15.82% | 0.00% |

Neither agent reached the 2048 tile during these evaluations.

### Initial Observations

- The Greedy Reward Agent achieved approximately 2.9 times the average total reward of the Random Agent.
- Its average maximum tile was more than twice that of the Random Agent.
- It reached the 256 tile in 63.6% of episodes, compared with 7.7% for the Random Agent.
- Its ineffective move rate was zero after adding the tie-breaking rule.
- Despite these improvements, the Greedy Reward Agent did not reach 2048, illustrating that maximizing immediate reward alone is not sufficient for consistently strong play.

These results provide initial baselines. Further comparisons should use consistent environment rules, evaluation conditions, and multiple random seeds to assess performance robustly.

## Running the Project

Run commands from the repository root with the project's virtual environment activated.

### Run tests

```bash
python -m tests.test_env
python -m tests.test_agent
```

### Run evaluation

```bash
python evaluate.py
```

The evaluation script saves per-episode results under `results/` and prints aggregate metrics to the terminal.

Check the configuration at the top of `evaluate.py` to select the agent, episode count, seed, and output CSV path.

## Roadmap

The project will gradually explore different decision-making and learning paradigms, including:

- Strategic heuristic agents
- Expectimax and Monte Carlo Tree Search
- Monte Carlo Control, Q-Learning, SARSA, and Expected SARSA
- Double Q-Learning and Dyna-Q
- Deep Q-Networks and distributional RL
- REINFORCE, Actor-Critic, and PPO
- Evolution Strategies
- Hierarchical and offline reinforcement learning
- Model Predictive Control and goal-conditioned RL

Each agent will be evaluated as it is implemented, with the aim of understanding how its underlying approach differs from previous agents.

## Project Philosophy

The focus is not simply to build an agent that reaches 2048. It is to understand how different approaches to decision-making behave, where they succeed or fail, and how their performance can be measured experimentally.

The project prioritizes incremental implementation, conceptual understanding, reproducible evaluation, and clear comparisons over adding complexity for its own sake.
